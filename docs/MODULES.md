# Модули Levels Tester

## Цель

Тестер проверяет полный исторический путь:

```text
H1 candles
  -> search: pivot и level
  -> confirmation: touch и подтверждение входа на M1/M5
  -> execution: виртуальная сделка
  -> evaluation: outcome и метрики
```

Все этапы получают данные только через replay cursor. UI не вычисляет торговую
логику.

## Доменные модули

### `configuration`

`StrategyConfig` содержит неизменяемую конфигурацию одного запуска: параметры
поиска, подтверждения, исполнения, outcome-профилей и detail timeframe.

### `search`

Ищет H1 pivot и строит уровни поддержки/сопротивления. Модуль отвечает за
кластеризацию, минимальные касания, отскок, touch и breakout. Он не знает о
M1/M5, сделках и API.

### `confirmation`

Получает `level.touched`, уточняет касание по detail-свечам и проверяет паттерн
подтверждения входа. Результатом является `TradeSetup`, а не сделка.

Состояния setup:

```text
WAITING_CONFIRMATION -> ENTRY_CONFIRMED
WAITING_CONFIRMATION -> CANCELLED | EXPIRED
```

### `execution`

Получает подтверждённый `TradeSetup`, рассчитывает entry/stop/take и моделирует
закрытие виртуальной позиции по detail-свечам. Текущий срез поддерживает базовый
stop buffer, RR, комиссии, проскальзывание и приоритет stop-loss внутри свечи.

### `evaluation`

Оценивает реакцию уровня и торговые результаты. Этот модуль не открывает и не
закрывает сделки.

## Replay и инфраструктура

`replay` является единственным владельцем исторического времени и вызывает
модули в порядке `search -> confirmation -> execution -> evaluation`.

`market_data` пока представлен пакетами `application` и `infrastructure`: он
загружает, проверяет и сохраняет свечи. Следующим шагом его интерфейс будет
выделен в отдельный domain port.

`persistence` хранит состояние запуска и данные. В текущем срезе полное
сохранение setup/trade ещё не завершено.

`api` и `web` только управляют запуском и отображают snapshot/events.

## Правила зависимостей

- `search` не импортирует `confirmation`, `execution`, `api` или `web`.
- `confirmation` не открывает сделки напрямую.
- `execution` не загружает данные из Binance.
- `evaluation` не меняет состояние уровня или сделки.
- `replay` координирует модули, но не содержит их внутренние правила.
- `api` и `web` не содержат расчёт торговой стратегии.
