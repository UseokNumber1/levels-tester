# Спецификация первого среза

Документ фиксирует правила, которые используются в `config/default.yaml` и
доменном ядре. Исторический интервал имеет границу `from` включительно и
`effective_to` включительно по `close_time`. Все даты нормализуются в UTC.

## Pivot

- Основной поток состоит из закрытых H1-свечей.
- В базовой конфигурации `wing=6`: свеча становится кандидатом только после
  закрытия шести правых свечей.
- Для максимума центральный `high` строго выше левой стороны и не ниже правой.
  Для минимума применяется зеркальное правило. Это оставляет первый экстремум
  в последовательности равных значений.
- Pivot хранит `pivot_time` центральной свечи и `confirmed_time` правой свечи.
- Фильтр объёма сравнивает объём центральной свечи с глобальным средним объёмом
  уже поступивших свечей. В базовой конфигурации минимальное отношение равно
  `0.5`.

## Levels

- Максимум создаёт resistance, минимум создаёт support.
- Pivot одного направления объединяются, если новый pivot попадает в текущую
  зону уровня. Цена объединённого уровня пересчитывается как медиана цен его
  исходных pivot.
- Зона симметрична относительно цены уровня и имеет ширину
  `max(price * zone_percent, tick_size)`. В базовой конфигурации
  `zone_percent=0.008`, `tick_size=0.01`.
- Первый pivot получает состояние `PENDING_REBOUND` и не участвует в активном
  уровне, пока после него причинно не наблюдается минимальный отскок.
- После отскока первый pivot переходит в `CREATED`; при накоплении двух
  подтверждённых pivot уровень переходит в `CONFIRMED`.
- При объединении pivot новый pivot учитывается только после требуемого
  отскока между исходным и новым pivot. Для resistance проверяется движение
  вниз от уровня, для support — движение вверх.
- Touch проверяется только по релевантному wick: `high` для resistance и `low`
  для support. Полное пересечение зоны диапазоном свечи само по себе touch не
  создаёт.
- В базовой конфигурации `breakout=wick`: выход релевантного wick за внешнюю
  границу зоны считается пробоем. Также поддерживаются `close` и `both`.
  Breakout обрабатывается до touch.
- Повторное событие touch создаётся после выхода цены из зоны и нового входа.
  Cooldown и повторный вход в базовом срезе не применяются.

## Replay

На каждом H1-bar строго выполняется порядок: сдвиг cursor, подтверждение
pivot, создание/объединение уровня, переходы уровня, outcome-профили,
публикация snapshot. В состояние не попадают свечи правее cursor. Скорость
является только параметром доставки событий и не меняет вычисления.

В текущем срезе M1/M5 загружаются лениво и отображаются только до H1 cursor.
Параметр `intrabar_policy` пока не влияет на расчёт: модель исполнения ордеров
будет добавлена следующим этапом без изменения H1-источника времени.

## Outcomes

Профиль создаёт отдельный результат для каждого touch. В базовой конфигурации
`quick_rebound` ожидает три H1-свечи, `patient_rebound` — восемь. Для resistance
успехом считается закрытие ниже уровня на `min_bounce_percent`, для support —
закрытие выше уровня на это значение. Breakout или истечение ожидания считаются
неуспехом.
